# 工作区管理方案（待审核）

基于 intent v1。新增能力由当前插件提供，原有插件更新功能保持独立。

## 批量归档
通过公开 ctx.contextMenus 注册 target=workspace 的「批量归档会话」菜单，打开带会话列表的对话框；支持勾选、全选当前可归档列表、显示选择数量和逐项结果，提供中英文文案。列表使用原生 workspaceRegistry 的工作区归属，不按 cwd 猜测归属。
客户端直接复用 ctx.workspaces.list 的原生快照与订阅，在当前工作区成员中选择 sessionIds，逐项调用 ctx.workspaces.archiveSession(sessionId)，沿用原生 Remote 权限，不新增 Host 批量端点或直接写存储。默认不传 stopActivity，不主动停止用户的模型回合、子代理、任务或定时工作；活跃会话保留原状并显示原生原因，其余会话继续归档。已归档项显示已完成，不做重复操作。原生服务负责归档状态持久化和取消置顶。
采用逐项成功/失败结果，不承诺整个批次原子成功；失败项可重新选择重试。UI 刷新使用原生订阅状态，批次提交期间阻止重复提交。

## 目录迁移：待确定可行边界
当前 DSH 0.2.2-rc.5 文档将 Workspace.path 定义为 readonly 且创建后不改，工作区成员资格又依赖 SessionHeader.cwd。因此修改运行中会话 cwd、仅新建同名工作区或仅修改显示路径都不能满足「工作区及历史会话一起迁移」的需求。
源码核对已确认不存在公开迁移接口：dsh-workspace/src/entity.ts:110-145 按 immutable header.cwd 和 workspace.path 校验归属；dsh-working-directory/src/index.ts:188-222 只追加 working-directory/change 事件，header 保持原始目录；dsh-session-persistence/src/index.ts:144-172 不提供更新 header 能力。需要原生提供工作区路径、历史会话 header 和运行态一致迁移的能力；不能在插件内绕过私有存储契约后宣称迁移成功。

用户于 2026-11-19 明确确认先实施上述批量归档方案，迁移保留为待解决需求。本次交付范围仅批量归档，A3 不属于本次验收；后续迁移需要原生能力与单独设计。

## 安全与兼容
保持现有 owner 网关控制，不放开工作区/会话的任意修改权限。不修改用户项目文件，不重写历史事件正文。新增工作区相关依赖应隔离注入，避免缺失可选工作区能力使已有插件更新服务不可用。
当前仓库基准 DSH 0.2.2-rc.1，与调查环境 rc.5 不同；实施前以实际采用 API 核对兼容范围，不能仅凭旧范围承诺支持。

## 组件隔离与 UI 修正（2026-11-19）
用户在两轮审查后明确要求「全部一起修正吧」。批量归档作为同一组合包中的独立可启停组件，复用 DSH 原生组件管理与持久化，不另建 npm 包或自定义开关存储。客户端加载不依赖更新 Remote；停用清理菜单、弹窗、订阅，停止后续请求而不撤销已发出请求；重新启用恢复新状态。
UI 使用公开 Checkbox、Modal、Button 和 DSH 语义颜色变量。全选及数量组成工具栏，失败重选仅在失败时显示；会话标题可换行，状态与错误置于所属行并区分层级，文案不保证活跃会话可归档。复用宿主字体与主题，不新增品牌配色。

## 验收草案
- A5 原生管理器可独立启停归档组件，更新功能不受影响；更新 Remote 故障不阻止归档加载，停用清理及重启无重复注册有生命周期测试。
- A6 原生 Checkbox、状态颜色、工具栏、长标题及双语文案按公开组件及语义主题契约对齐；源码审查、构建与相关测试通过。遵循用户明确要求，不进行真实 GUI 视觉实测。
- A1 同一工作区多选归档，准确显示成功、失败和已归档结果，不影响未选或其他工作区会话。
- A2 活跃会话归档失败时保留运行状态，其余所选可归档会话仍能完成；owner 权限及输入边界有效。
- A3 目录迁移保留工作区归属与历史记录，后续会话使用新目录；需先确定受支持实现，不能用仅改变当前 cwd 的测试替代。
- A4 中英文控件与文案经源码及组件测试核对，构建与相关集成测试通过。用户明确禁止修改本机已安装插件，要求以后插件更新后不进行真实 GUI 验证；本次及后续交付以源码、构建、自动化测试和打包检查为准，不将真实 GUI 作为必需验收。
