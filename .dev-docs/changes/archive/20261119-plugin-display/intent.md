# 修复插件与组件展示信息

## 原始诉求与来源

用户于 2026-11-19 在当前会话提供插件组件列表与工作区菜单截图，并要求：“1. 组件名字有问题 2. 插件名字也要调整 3. 批量归档会话前少了图标。这些问题都需要修复一下。另外插件描述和组件描述也调整一下。”

## 问题、用户与场景

插件管理页将归档组件显示为 file URL 且缺少描述，更新组件沿用整体插件名称与泛化描述；整体插件名称和描述没有涵盖新增的会话归档功能。工作区菜单中的批量归档操作缺少与原生菜单一致的图标。

## 目标与成功结果

整体插件及两个组件使用清晰、准确且中英文对应的展示名称与描述；归档组件不再以文件路径作为主标题；“批量归档会话”显示归档图标。

## 范围与非目标

修复展示元数据的加载方式、双语文案及归档菜单图标，更新相关使用说明并验证发布产物。此次请求不包括新增工作区迁移、改变归档语义或更新队列逻辑，也未要求提交、推送、发布或安装。

## 约束与相关基线

基于 workspace-batch-archive-migrate 分支的提交 5a6442e8aa7fc1e535560b71367fdf81c984b756，在独立 fix-plugin-display 分支实施后续修正。之前 change 20261119-workspace-management 已归档，只引用其成果，不改写其历史。

当前知识入口为 `.dev-docs/index.md`；用户说明位于 `README.md` 第 32–42 行；开发约束位于 `AGENTS.md`。继承同一 bundle 中两个组件独立启停、双语界面、复用 DSH 原生接口的设计。遵循用户既有约束：禁止修改本机已安装插件，不做真实 GUI 验证，以源码契约、自动化测试、构建与打包检查验证。

## 依赖、假设与待决事项

需要核查宿主对包子路径、组件 locale 和图标的公开加载契约，不能将 README 现有“技术路径展示限制”当作无解结论。展示名称和描述的具体推荐随 spec 一次展示审核；npm 包名与组件 ID 应保持稳定，除非必要契约调查证明必须调整。
