# 插件增强 · Plugin enhance

为 DSH 的插件管理页增加「更新」标签页，支持检查更新、勾选批量更新、一键更新全部可更新项，以及重试失败项。支持市场、npm 和 GitHub 来源，包含英文与简体中文界面。

包名：`dsh-plugin-enhance` · DSH 兼容范围：`>=0.2.1-rc.5 <0.3.0-0`（开发与测试基准为 `0.2.1-rc.5`）。

允许后续 `0.2.x` 升级，DSH 兼容性检查也包含此范围内的预发布版本；`0.3.0` 及其预发布版本需另行验证。

## 安装

通过 DSH 官方插件管理器安装并启用。以 `web` profile 为例：

```sh
dsh plugin --profile web add dsh-plugin-enhance@latest
```

也可以按 GitHub 地址 `github:urzz/dsh-plugin-enhance` 安装。安装时无需额外构建。

## 使用

1. 打开 DSH 的「插件 → 更新」。尚未检查时会自动开始检查，先展示组合包清单，再逐项显示检查结果；也可点击「检查更新」手动刷新。
2. 默认查看全部插件，可切换「可更新」「需处理」筛选，或按插件名称、来源搜索。列表显示当前版本、目标版本、启用状态和来源。
3. 点击行内「更新」更新单项；也可勾选项目后点击「更新所选」，或点击「更新全部可更新项」。全选仅选择当前筛选结果中可更新的项目。
4. 更新失败时查看原因，处理后点击行内「重试」或「重试失败项」。

列表按状态分组，同组内按名称排序。检查、更新进度及成功和失败结果都会保留在默认列表中；「更新须知」可展开查看更新机制与注意事项。

更新单位为 **bundle（组合包）**：同一包中的多个插件会一起更新，并保留原启用状态；底层管理器可能改变插件选择顺序。更新队列串行执行。

## 支持的更新来源

仅选择比当前版本更新、且兼容当前 DSH 的目标，不自动授予兼容性豁免。

| 来源 | 更新目标 |
| --- | --- |
| 已配置的插件市场 | 优先采用市场默认版本及其明确的安装目标。 |
| 标准 npm 包 | 查询 `latest`，沿用当前 profile 的 registry、认证和代理设置。 |
| GitHub 仓库 | 查询原来源对应分支、标签或 commit 的根目录 `package.json`；未指定 ref 时查询默认分支。 |

市场读取失败时会显示错误，不会静默切换到其他来源。

GitHub 地址支持 `github:owner/repo`、`owner/repo`、GitHub HTTPS 和 SSH Git 地址，可带 `#分支`、`#标签` 或 `#commit`。查询使用本机 Git 的代理和认证配置，不执行仓库代码或构建脚本。

GitHub 更新以 `package.json` 的版本号为准，同时要求包名一致、声明 bundle 且兼容当前 DSH。**相同版本下的 commit 变化不会触发更新。** 更新保留原 ref，继续跟踪同一分支；固定标签或 commit 不会自动切换到默认分支。暂不支持 `#semver:`、子目录及其他 pnpm Git ref 扩展。

支持更新本插件自身，使用相同的来源和兼容性规则，并排在本批其他项目之后执行。重载期间更新标签页可能短暂消失；新实例会继续显示当前进程中的队列状态。若自身安装或激活失败导致标签页未恢复，可运行 `dsh plugin --profile web add dsh-plugin-enhance@latest` 重新安装（其他 profile 请替换 `web`）。

随安装附带的内置包、不可移除包、本地路径，以及无市场目标的非 GitHub Git、压缩包 URL 和 npm alias 来源不参与更新。市场明确提供的 Git 安装目标可以使用。

## 更新失败与注意事项

- **更新不是原子操作。** 支持 HMR 时会先卸载旧包再安装指定版本；安装失败可能留下未安装的组合包。页面会保留恢复目标，处理原因后可重试。
- 无 HMR 时，仅在管理器返回 `stop-profile` 的情况下直接覆盖安装，并提示是否需要重启；其他卸载失败不会继续安装。
- 待授权构建脚本、安装失败、激活失败或实际版本不符均不会显示为成功。构建脚本需通过官方插件管理器另行授权，本插件不会自动授权或重启 DSH。
- GitHub 分支可能在检查与安装之间前进；如果实际安装版本与检查目标不符，会报告失败。
- 恢复队列只保存在当前进程中，重启后会丢失。此时可使用官方管理器按原包名安装所需版本；本插件不提供自动回滚。
- 更新前会核对来源、版本及启用状态是否变化。执行更新期间，请避免同时从其他入口管理同一包。

## 模型工具

可以让 DSH 中的智能体使用 `plugin_enhance` 检查和执行更新，结果与网页共用同一更新队列。

| 操作 | 用法 |
| --- | --- |
| `check` | 检查更新，返回候选列表和 `generation`。 |
| `status` | 查看队列进度与结果。 |
| `start` | 使用 `check` 返回的 `generation` 及包名数组 `names` 启动更新。 |
| `retry` | 重试指定 `names`；省略时重试所有可恢复项。 |

工具遵守 DSH 的完整访问权限与审批机制，未获授权时不修改 profile。

## 配置

可在 bundle 配置中覆盖以下字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `pnpmCommand` | `pnpm` | npm 元数据查询使用的命令；profile 自带的包管理启动器优先。 |
| `lookupTimeoutMs` | `20000` | 元数据查询超时，单位为毫秒，适用于 npm 和 GitHub 查询。 |
